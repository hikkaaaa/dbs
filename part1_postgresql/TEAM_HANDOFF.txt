TRANSACTIONS AND SCRIPT EXECUTION

01/02/03/00 scripts have their own BEGIN/COMMIT boundaries. Execute each complete
script using a driver mode that permits multiple SQL statements and let the
script own the transaction. For example, a SQLAlchemy engine created with
isolation_level='AUTOCOMMIT' can supply a raw psycopg 3 connection; execute the
whole script without parameters using cursor.execute(script, prepare=False).
Test that approach with your installed driver. Do not naively split at semicolons:
04/05 contain DO blocks with internal semicolons. Alternatively implement DDL and
seed inserts using SQLAlchemy itself, with identical names and constraints.
Do not run these transaction-owning scripts inside engine.begin(); use an ordinary
SQLAlchemy transaction for each independent Part 2 update/delete and roll it back.

These checks are deliberately NOT database triggers. Implement both, in related
transactions, and demonstrate rejected operations in the deployed application.

1. Prevent self-reviews.
   Before inserting/updating a review, test whether the proposed reviewer_id
   occurs in paper_author for the proposed paper_id; reject if it does.
   Also validate proposed authorship changes against that paper's existing
   reviewers. Adding an author who already reviewed the paper must be rejected.
   Example rejection: paper 1 + reviewer 1 (Arman is its author).
   Author-change rejection: add reviewer/author 4 to paper 12 (review 16 exists).
   Check changing a review's reviewer OR paper, as well as creating a review.

   If paper.session_id is not NULL, require status='accepted' and require
   paper.track_id -> track.conference_id = session.conference_id.
   Recheck when assigning/changing a session, paper status or paper track, and
   when changing a session's conference. Changing a track's conference can also
   invalidate assignments; validate it if you expose that optional workflow.
   Either reject the change or remove the invalid assignment in one transaction.

   Later invalid status: change scheduled paper 1 from accepted to rejected.
   Later invalid track: move scheduled paper 1 to track 4.
