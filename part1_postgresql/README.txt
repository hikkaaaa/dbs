CSCI 341 ASSIGNMENT 3 - PART 1: POSTGRESQL HANDOFF
Prepared for Umida Turmaganbet and teammates

START HERE

This package implements the relational schema and fictional sample data for
Part 1. It follows Umida's Assignment 1 design and Assignment 3 Appendix A.
SQL files contain ordinary PostgreSQL SQL, without psql-specific commands.
Names are lowercase and unquoted; use these exact names in the teammates' code.
The tables are created in the connection's default schema (normally public).
Use a dedicated database and the default public schema for this project.

FILES

00_restore.sql          Self-contained schema + seed + schedule view. Re-runnable.
01_schema.sql           Creates 15 tables, constraints, and indexes in an empty DB.
02_seed.sql             Replaces data in those tables and resets identity sequences.
03_schedule_view.sql    Optional handoff support for Part 2 task 8; real SQL view.
04_verify.sql           Checks original seed data and reports every table's count.
05_constraint_tests.sql Tests rejection of bad data and deletion actions; rolls back.
README.txt              Setup, schema, keys, deletion actions, assumptions.
TEAM_HANDOFF.txt        Query fixtures and required application responsibilities.
VALIDATION.txt          Actual validation results and environment limitations.

IMPORTANT: 00_restore.sql drops and rebuilds the listed project tables and view.
02_seed.sql clears all rows in the listed project tables. Use either only in a
dedicated assignment database. Neither drops the database or the public schema.
No foreign keys are disabled. Restore stops if an unrelated object depends on a
project table, rather than cascading deletion into unrelated objects.

QUICK START WITH POSTGRESQL AND psql

Install PostgreSQL server plus the psql/createdb/pg_dump command-line tools using
your operating system's installer. A local server or a hosted PostgreSQL DB works.
This package targets PostgreSQL 17; no extensions or superuser privileges needed.
See VALIDATION.txt for the exact engine used to check the delivered scripts.

Open a terminal inside this extracted folder. Create a fresh database once:

    createdb -U postgres conference_assignment

Restore all objects and sample data, then verify:

    psql -X -U postgres -d conference_assignment -v ON_ERROR_STOP=1 -f 00_restore.sql
    psql -X -U postgres -d conference_assignment -v ON_ERROR_STOP=1 -f 04_verify.sql
    psql -X -U postgres -d conference_assignment -v ON_ERROR_STOP=1 -f 05_constraint_tests.sql

Replace postgres with your local database role. Use -h localhost if your setup
requires TCP connections. Add -p PORT for a nondefault port. Let the client prompt
for your password; do not put real credentials in shared files or screenshots.
If your account cannot create databases, ask the hosting provider/admin to create
one, then connect to that dedicated database and run the same SQL files.

Alternative, to demonstrate creation and insertion separately in a fresh DB:

    psql -X -U postgres -d conference_assignment -v ON_ERROR_STOP=1 -f 01_schema.sql
    psql -X -U postgres -d conference_assignment -v ON_ERROR_STOP=1 -f 02_seed.sql
    psql -X -U postgres -d conference_assignment -v ON_ERROR_STOP=1 -f 03_schedule_view.sql

Do not run 01_schema.sql again on existing tables. Use 00_restore.sql to rebuild.
To restore just the original seed after mutations, run 02_seed.sql; the view stays.
The seed script is repeatable and sets next generated IDs above the supplied IDs.

QUICK START WITH pgAdmin

1. Connect to your PostgreSQL server and create conference_assignment.
2. Open Query Tool specifically for that database.
3. Open 00_restore.sql and execute the entire file.
4. Open and execute 04_verify.sql. Check the Messages and Data Output panels.
5. Optionally run 05_constraint_tests.sql; expected rejections appear as notices.
6. Refresh Schemas > public > Tables and Views to inspect the objects.
If a statement fails and the session is in an aborted transaction, issue ROLLBACK;
before correcting the error and re-running the file. Do not execute isolated
fragments of the test file; its outer ROLLBACK preserves the initial dataset.

SCHEMA DOCUMENTATION

PK = primary key, FK = foreign key, UQ = uniqueness constraint.
Every column is NOT NULL unless explicitly listed as optional below.
All six standalone generated keys are INTEGER GENERATED BY DEFAULT AS IDENTITY.
IDs in author/reviewer are inherited user IDs, not separate generated identities.

Table                   PK                         Other keys and references
----------------------  -------------------------  ----------------------------
app_user                user_id                    UQ email
author                  author_id                  FK -> app_user.user_id
author_research_area    (author_id, area_label)     FK author_id -> author
reviewer                reviewer_id                FK -> app_user.user_id
reviewer_expertise      (reviewer_id, area_label)   FK reviewer_id -> reviewer
conference              conference_id              No additional unique key
conference_host         (conference_id, host_name) FK conference_id -> conference
conference_reviewer     (conference_id, reviewer_id)
                                                   FKs -> conference, reviewer
track                   track_id                   FKs conference_id -> conference;
                                                   coordinator_id -> reviewer;
                                                   (conference_id, coordinator_id)
                                                   -> conference_reviewer
conference_session      session_id                 FKs conference_id -> conference;
                                                   chair_id -> reviewer;
                                                   (conference_id, chair_id)
                                                   -> conference_reviewer
paper                   paper_id                   FKs track_id -> track;
                                                   session_id -> conference_session
paper_keyword           (paper_id, keyword)         FK paper_id -> paper
paper_author            (paper_id, author_id)       FKs -> paper, author;
                                                   UQ (paper_id, author_position)
paper_version           (paper_id, version_no)      FK paper_id -> paper
review                  review_id                  FKs paper_id -> paper,
                                                   reviewer_id -> reviewer;
                                                   UQ (paper_id, reviewer_id)

Additionally, paper_author has a partial unique index on paper_id WHERE
is_corresponding. This enforces at most one corresponding author per paper.
It does not guarantee that a paper has any corresponding author.

OPTIONAL COLUMNS / DATA TYPES

Nullable: author.orcid, paper.session_id, paper_version.change_note,
review.confidential_comments. All other attributes are required.

INTEGER: IDs, years_experience, author_position, version_no, overall_score.
BOOLEAN: paper_author.is_corresponding.
DATE: conference dates/deadlines, paper.submission_date,
      conference_session.session_date, review.review_submission_date.
TIME: conference_session.start_time/end_time (local conference time).
TIMESTAMP WITH TIME ZONE: paper_version.uploaded_at (seed supplies UTC offsets).
TEXT: names, descriptive labels, status, recommendation, phone numbers,
      ORCID, email, file locations, abstracts, and comments.

Phone numbers are text so '+' and leading zeros are preserved. File locations
are fictional relative paths, not uploaded PDFs. There is no file upload feature.
Only completed reviews are stored: score, recommendation, author comments and
submission date are mandatory. Blank/space-only author comments are rejected.
All seed ORCIDs are NULL; ORCID is optional and no validation rule was specified.

REQUIRED DATABASE CONSTRAINTS

- PK/FK/NOT NULL and unique email, author positions and reviewer-paper pairs.
- status IN ('submitted','under review','accepted','rejected','withdrawn').
  Use 'under review' exactly, including the space, in Python and forms.
- overall_score is INTEGER, 1 through 5; recommendation IN ('accept','reject').
- author_position and version_no are positive integers.
- years_experience is a nonnegative integer.
- end_date >= start_date; session end_time > start_time.
- Version identity is (paper_id, version_no); gaps are allowed. Current version
  means MAX(version_no) per paper. There is no separate current-version flag.
- A single nullable paper.session_id gives at most one session per paper.
- Paper deletion cascades to paper_author, paper_keyword, paper_version, review.

DELETION ACTIONS

- app_user -> author/reviewer profiles: CASCADE. Deletion can still be blocked
  if an author/reviewer is referenced by a paper, review, pool, track or session.
- author -> research areas; reviewer -> expertise: CASCADE.
- author -> paper_author: RESTRICT. Remove/reassign authorship deliberately.
- reviewer -> pool membership, reviews, coordinator/chair references: RESTRICT.
- conference -> host names and pool memberships: CASCADE.
- conference -> tracks/sessions: RESTRICT. Deleting a populated conference
  requires deliberate dependent cleanup; users/reviewers are never cascaded away.
- pool membership -> coordinating tracks/chairing sessions: RESTRICT.
- track -> papers: RESTRICT.
- session -> paper.session_id: SET NULL (unschedule, preserve the paper).
- paper -> all four dependent tables: CASCADE.
- No ON UPDATE CASCADE is used; IDs are treated as stable identifiers.

No triggers are included. There is no rule requiring review authors to be in a
particular conference's reviewer pool; Assignment 1 specifies that restriction
for coordinators/chairs. Additional review-assignment rules have not been invented.
The final group README must say which optional application rules are implemented.

DESIGN MAPPING AND ASSUMPTIONS

- USER is named app_user and SESSION is conference_session to avoid confusing
  SQL terminology. The conceptual entities and relationships are preserved.
- AUTHORS becomes paper_author with its author_position and is_corresponding.
- MAINTAIN_POOL becomes conference_reviewer.
- Multivalued labels/names become author_research_area, reviewer_expertise,
  conference_host, and paper_keyword. They are attribute relations, not new
  independently identified domain entities. No comma-separated lists are stored.
- Each track has ONE research_area label. Affiliation and room are scalar labels.
- The missing UML attribute multiplicities are interpreted from Assignment 1:
  research/expertise/host/keyword collections 1..*, optional fields 0..1, and
  other specified attributes exactly 1.
- USER specialization is complete and overlapping: every seed user has at least
  one role; the same user_id can appear in both author and reviewer tables.
- The version weak entity is identified by (paper_id, version_no).
- Emails use ordinary PostgreSQL text uniqueness (case-sensitive). The app may
  normalize input to lowercase consistently; the seed uses lowercase addresses.
- No uniqueness of conference acronym or ORCID is assumed. Conference editions
  have separate IDs. No score-to-recommendation or final-status rule is imposed.
- There are no invented date-ordering constraints on deadlines. Seed submissions,
  versions, reviews and sessions nevertheless have sensible chronological dates.
- Session date is within its conference dates in the seed; automatic enforcement
  of that additional consistency condition is not implemented.
- All names/institutions/content are fictional demonstration data. The two named
  people and their emails are included exactly as Assignment 3 requests.
